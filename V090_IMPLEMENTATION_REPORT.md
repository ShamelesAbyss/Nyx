## 1. Architecture and authority changes

The existing ObjectiveExecutionEngine remains the orchestrator and completion owner. WorkbenchAuthorization gains default-null combined development approval, bound once to the objective's original canonical project/environment/guest and exact output→artifact mappings. Current ViewModel/service configuration preserves that scope through monotonic latest snapshots; global terminal opt-out refuses rather than redirects resume. Workbench displays the original approved project, recovery errors and export limitations. Artifact-only objectives retain their legacy terminal-disabled scope.

Combined development holds the existing terminal workspace lease through source repair, fixed commands, selected snapshots and registration. Typed FixedProjectExecution observations require unique same-task/objective/scope operations, infrastructure completion and latest ordered successful BUILD→TEST. Selected textual bytes are bounded to 128,000 bytes per output and copied through WorkbenchStore.registerVerifiedSnapshot, using existing formats/quotas/atomic storage. Observed and registered provenance are checkpointed before a registration-kind write witness is published. A failed checkpoint can leave retained bytes without a witness; those bytes cannot become completed work by model prose or a generic write tool. Selected destinations cannot be forged through model write/bundle tools. Mandatory internal verification runs separately from the eight-declaration budget.

Model terminal admission is a fixed validated argv catalog with absolute trusted tool paths, not arbitrary shell/executable/programmable utility/Git syntax. Source operands, canonical parent/targets, link counts, batch transport, exclusive workspace temporaries/probes and fixed compiler output guards are checked. Controlled env-i happens before bash startup. Command identity binds bounded semantic arguments/cwd/policy and actual script digest; source payloads/credentials are not added to the journal. Explicit manual shell and approved project code retain separate authority.

Capability support defaults to UNKNOWN and promotes only completed locally validated behavior. ModelIdentity.fromRequest uses actual effective revision/context/threads/temperature/output/schema/think/tools, with independent evidence expiry/merge. Adapter API availability is not model support; reasoning observation is not thinking-control acceptance. Activity watchdogs in Fabric, AgentRunner and direct OllamaClient count genuine reasoning/text without treating reasoning as answer text or evading finite hard deadlines. Continuation next/done schemas and checkpointed decision ordinals prevent initial step-ID reuse; Full uses one bounded whole-DAG profile, exact evidence prerequisites and whole-list worker validation.

Service generation ownership survives cancelled cleanup; per-run lease predicates protect checkpoints/finalization. Timeout-like or unknown external results retain uncertainty. Manager-owned persistent launch now synchronously commits a pending token/mode/guest namespace fence before dispatch, and unknown/adopted/reused PID/start/command cannot authorize clean stop. No naked-PID/session-tree teardown or blind retry/reset is added. Availability is intentionally conservative: unresolved fences may remain stuck after external cleanup.

Workbench repairs exact numeric manifest validation, re-verifies deduplicated source bytes and rejects ZIP namespace aliases. Export verifies local bytes before opening a destination and reports partial writes/retry without claiming remote durability. Application network gates separate public HTTPS from explicit local/LAN inference, validate actual DNS/connected routes/every public redirect, enforce credential/origin rules and reject gateway query endpoints. Platform cleartext remains permitted for authorized LAN compatibility; it is not a firewall. Prepared CI/packaging gates independently inspect identity/signers/ABI/ELF+ZIP alignment/notices/source bytes/checksum coverage; hosted execution remains unverified.
