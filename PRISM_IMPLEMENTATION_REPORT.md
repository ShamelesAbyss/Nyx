## Architecture and preserved capabilities

`ui/prism/PrismDesign.kt` provides shared Eclipse surfaces, scalable type (legacy small text floor 12sp), 48dp actions, inputs, wrapping action rows, adaptive pairs and saveable disclosures. Section accents identify Chat, Models, Agents, Autonomy, Arsenal, Gateways, Workflows, Performance and Settings. `PrismShell` owns compact primary navigation, complete Sections menu, scrollable expanded rail, connection/model context, explicit mission link and destination SaveableStateHolder. Autonomy’s three nested modes have their own stable SaveableStateHolder so switching Objectives/Terminal/Workbench retains in-progress drafts. At large text sizes fewer primary entries leave room for labels; all destinations remain in Sections. Width >=840dp selects the rail; two-pane content uses actual available width >=720dp. Safe drawing/IME insets are consumed once at the shell, with safe-area long-text dialogs.

MainActivity retains all existing screen implementations and operational callback owners behind a testable `NyxDestinationContent` boundary. The only ViewModel change clears stale selected-objective presentation data and fences DAO collectors against late updates from another selection. Execution methods are byte-identical to baseline. No engine, data/schema, provider, native/C++, permissions, SDK, dependency or managed recovery change.

The complete [control matrix](docs/prism/CONTROL_PRESERVATION.md) and [machine-readable baseline](docs/prism/control-inventory.json) archive 235 primitive control call sites and 134 ViewModel binding occurrences, including dynamic templates. The static gate rejects lost handler counts (one explicitly reviewed relocation: console Resume opens existing recovery confirmation), unexpected protected production edits and ViewModel changes outside selection. This is source preservation evidence, not a claim that each privileged control was executed on a device. Composite/custom controls and conditional content retain their original screen bodies and callbacks. Technical task records, history, Terminal, Workbench, imports, diagnostics and advanced settings remain accessible.

## Mission Results and evidence

`MissionResults.present` is a deterministic read-only projection with no provider, network, terminal, filesystem or authorization API. It filters tasks/events/reports by objective and task ownership; parses bounded JSON; requires completed tasks, recorded passed verification and a nonempty all-boolean-passing check array. Invalid/coercive/malformed/deep records cannot become verified success. Missing evidence stays incomplete. Recorded elapsed time rejects negative clocks.

Evidence inputs: existing ObjectiveEntity status/title/error/timestamps; ObjectiveTaskEntity status/outcome/evidenceJson/workerKind; ObjectiveEventEntity execution_config, owned quick_operation_evidence and quick_project_execution; existing ObjectiveArtifactEntity text reports; owner-matched WorkbenchManifest registrations and retained source URLs. QuickAction snapshots are validated by the existing original-objective validator. Inspection JSON is translated only with matching owned successful project_inspect evidence. It explains empty workspaces, markers, tools, root source names and readiness without model inference. Fixed tests show retained real exits/procedures/stdout/stderr. Existing-artifact verification explicitly creates no new file and does not prove factual accuracy. Development paths are recorded edits, not newly verified bytes. Plain model output stays observed text rather than proof of file existence or citations. Records are sanitized/redacted before display/copy.

`MissionResultsCard` exposes status, summary, recorded checks, facts, actual task output, full scrollable reader, bounded explicitly labeled copy, technical details and real available Workbench/recovery actions. Historical selection wins over another live mission and is read-only. Legacy console Pause/running indicators and live model output are bound to the displayed mission’s actual ExecutionMonitor ID, preventing an older result from controlling or displaying another mission’s run. The full-output reader saves only its output index, avoiding large output strings in Android saved state. Raw persisted records open the existing repaired console. Approved owner-matched file rows invoke the unchanged ViewModel preview/prepare-export/SAF save/share paths, which recheck original-objective ownership and current private-store bytes. Failed registrations disable save/share. Mission pause/cancel appear only for the matching active execution. Quick Action retries require fresh explicit selection/approval; no automatic replay.

## Known limits and release blockers

A compatible ARM64-translation emulator was available and the exact release APK was exercised there. The API 30 x86_64 Google APIs AVD used `libndk_translation`, a 360×640/160 dpi compact window, a 1000×800 expanded window and 170% font scale. All nine destinations rendered, the expanded rail exposed all nine entries, and the exact APK updated in place over public v0.9.2.1 with `versionCode` 27 and a `files/upgrade-marker.txt` marker retained. This is emulator evidence, not physical-hardware acceptance. Physical folding/unfolding, real IME/rotation/split-screen/process-death recreation, TalkBack traversal, real Termux/PRoot/managed-server ownership, real Ollama/native inference, SAF/share recipients, permission denial/recovery and real-model timing remain **unverified**. Host screenshots and emulator captures are render evidence, never hardware claims. File registry counts are metadata and are rechecked only by existing file actions. Results cannot upgrade incomplete legacy evidence into success. Large clipboard copies are explicit 60,000-character excerpts; full text remains scrollable.

Codex's local generated debug signer `85c5ec6f1483b010f4b864f2c56d5821eb56c0877ff2eb40d236b2d1f1c67747` was build-only and was not used for the release. Manus rebuilt and packaged with the established certificate `aa188be93aff8afda48936af2ddc4ee3e9a02a0cc6b4607addb09c8dd3a6bb55`; both published APKs match it and pass the existing signer gate.
